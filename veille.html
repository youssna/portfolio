3. Comprendre React

Les concepts de base expliqués simplement.

C'est quoi React ?

React est une bibliothèque JavaScript créée par Meta (Facebook) en 2013. Elle sert à construire des interfaces web. C'est aujourd'hui l'outil le plus utilisé en entreprise pour le développement Front-End, devant Vue.js et Angular (source : State of JS 2024).

Comment ça fonctionne ?

React découpe le site en composants indépendants : un composant pour le menu, un pour un bouton, un pour une carte produit... Chaque composant est réutilisable et se met à jour automatiquement quand les données changent, sans recharger toute la page.

4. Comparaison : PHP sans framework VS React

Ce que React change concrètement par rapport à du PHP classique côté interface.

Critère PHP sans framework (côté client) React
Rechargement de page À chaque action, la page entière se recharge depuis le serveur. L'écran devient blanc le temps du chargement. Aucun rechargement. React met à jour uniquement la partie de la page qui change. L'expérience est fluide et instantanée.
Organisation du code Le HTML et la logique PHP sont souvent mélangés dans les mêmes fichiers. Sur un gros projet, ça devient difficile à maintenir. Le code est découpé en composants réutilisables. Chaque composant a sa propre logique et son propre affichage, ce qui facilite le travail en équipe.
Mise à jour de l'interface Pour afficher une nouvelle donnée, il faut réécrire du HTML ou manipuler le DOM manuellement avec JavaScript. React gère automatiquement la mise à jour via le Virtual DOM : il compare l'état avant/après et ne modifie que ce qui a changé.
Réutilisation du code Un élément (ex: une carte produit) doit souvent être recopié manuellement d'une page à l'autre. Un composant React se crée une seule fois et s'utilise autant de fois que nécessaire sur tout le projet.

5. Les dernières grandes mises à jour de React

Les changements majeurs survenus en 2024–2025 que je surveille dans le cadre de ma veille.

🚀 React 19 — Décembre 2024

Version majeure

La mise à jour la plus importante depuis des années. Elle introduit le React Compiler : un outil qui optimise automatiquement les performances du site. Avant, les développeurs devaient ajouter manuellement du code pour éviter les ralentissements. Désormais, le compilateur le fait seul. Le code est plus simple à écrire et les sites plus rapides.

Lire l'annonce officielle

⚡ Les React Server Components — 2024

Standardisation

Historiquement, React s'exécutait uniquement dans le navigateur. Les Server Components permettent à certains composants de s'exécuter directement sur le serveur. Résultat : moins de code envoyé à l'utilisateur, chargement plus rapide, et meilleur référencement Google (SEO). C'est désormais le standard dans Next.js 14+.

Comprendre les RSC

📝 Les "Actions" pour les formulaires — React 19

Nouvelle fonctionnalité

Avant, gérer un formulaire en React demandait beaucoup de code : indicateur de chargement, gestion des erreurs, retour utilisateur... Les nouvelles Actions (et le hook useActionState) simplifient tout ça en quelques lignes. C'est l'une des améliorations les plus attendues par les développeurs.

🔮 6. Prévisions et avenir de React

D'après les dernières mises à jour et les tendances du marché, je prévois plusieurs évolutions pour les prochaines années.

Le React Compiler marque le début d'une automatisation croissante : les outils se chargeront de plus en plus des optimisations à la place du développeur. Le code sera plus simple à écrire, et le développeur pourra se concentrer davantage sur la logique métier.

La frontière entre développeur front-end et full-stack va continuer de s'effacer avec Next.js, qui permet de gérer à la fois l'interface et le serveur dans une seule application React.

Enfin, des alternatives comme Svelte ou Astro gagnent du terrain pour les sites vitrines. React reste dominant sur les applications complexes, mais la concurrence pousse l'écosystème à innover constamment.

7. Bilan : Où en suis-je ?

Au début de mon BTS, j'ai volontairement choisi de coder mes projets sans framework, comme Loca'Vélo en PHP pur. C'était indispensable pour acquérir des bases solides en HTML, CSS, JavaScript et PHP natif.

Je n'ai pas encore utilisé React sur un projet en production. Actuellement, je suis en phase d'apprentissage : je lis la documentation officielle, je suis des tutoriels, et je crée de petits composants pour comprendre la logique de l'outil.

Cette veille me permet d'anticiper les attentes des entreprises : arriver sur le marché du travail en connaissant déjà le vocabulaire, les concepts et les derniers standards de React.
